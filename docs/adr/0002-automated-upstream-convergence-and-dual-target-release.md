# Automated Upstream Convergence and Dual-Target Plugin Release Pipeline

Status: accepted

Because `BLACK-BIRTHDAY/cpa-plugin-aistudio2api` maintains custom host-affinity routing, cooldown fail-fast propagation, and single-hop channel waterfall logic on top of upstream `jianli9158/cpa-plugin-aistudio2api`, routine upstream releases frequently touch shared runtime and C ABI files (`internal/app/*`, `internal/cpa/*`, `internal/aistudio/*`). Furthermore, the plugin is deployed exclusively to two runtime environments: the GCP Cloud Run gateway (`linux/amd64`) and local Windows x64 desktops (`windows/amd64`).

We decided to:
1. **Restrict Build Matrix to Gateway (`linux/amd64`) and Local Desktop (`windows/amd64`)**: Remove `darwin/arm64`, `darwin/amd64`, `linux/arm64`, and `windows/arm64` targets from `.github/workflows/release.yml`, running all builds on `ubuntu-24.04` using GNU static libraries (`linux-amd64-gnu`) and `llvm-mingw` (`windows-amd64`).
2. **Publish In-Place Version Releases Aligned with `PluginVersion`**: Treat `PluginVersion` in `internal/cpa/config.go` as the single source of truth, automatically synchronizing `registry.json` (`version`) and recreating the `v<PluginVersion>` GitHub Release (`--latest`) at `HEAD` with `aistudio2api_<PluginVersion>_linux_amd64.zip`, `aistudio2api_<PluginVersion>_windows_amd64.zip`, and `checksums.txt` so `CLIProxyAPI` `internal/pluginstore` semver tag and asset validations succeed.
3. **Run Scheduled Upstream Sync with 30-Turn Agentic Conflict Resolution and Cold-Start Resilience**: Schedule `.github/workflows/upstream-sync.yml` (`0 1 * * *` UTC and `workflow_dispatch`) to fetch the latest formal release tag from `jianli9158/cpa-plugin-aistudio2api`, merge with `--no-commit --no-ff`, and verify via `gofmt -w .`, `go vet ./...`, CGO shared-library build (`-buildmode=c-shared`), and unit tests. When merge conflicts or verification failures occur, `scripts/ci-upstream-agent.mjs` invokes a 30-turn (`maxTurns = 30`) tool-calling LLM repair loop (`UPSTREAM_AGENT_BASE_URL` / `UPSTREAM_AGENT_API_KEY` / `UPSTREAM_AGENT_MODEL`) bounded by the verification gate, using gateway pre-warming and retry backoff (`429`/`502`/`503`/`504`/network timeouts) to tolerate Cloud Run container and plugin worker cold starts before promoting to `main` and chaining into `release.yml` via `workflow_call` (or quarantining to `upstream-sync/failed-<sha>` with a diagnostic GitHub Issue).
